# 직관 기록과 승리요정 승률 — 설계

작성 2026-09-28.

## 왜

다른 K리그 팬앱(Kick, KickON)에는 직관 기록과 "승리요정"이 있고, 포항 전용 팬앱은 없다. 내가
다녀온 경기를 남기고 그 경기들의 승률을 보는 것은 기록을 보여 주는 앱을 "포항 팬의 앱"으로
바꾸는 기능이다. 자료는 사용자 자신의 기록이라 저작권 부담이 없다.

## 잘 됐다고 보는 기준

- 경기 상세에서 한 번 눌러 "직관했어요" 를 표시할 수 있다
- 마이 탭에서 "7경기 · 71%" 처럼 곧바로 보이고, 눌러 들어가면 기록 목록과 요약이 있다
- 사진 한 장을 찍거나 골라 남길 수 있고, 본인만 본다

## 정한 것

| 질문           | 결정                                                                |
| -------------- | ------------------------------------------------------------------- |
| 직관 표시 방법 | 스스로 체크. 위치 인증 없음                                         |
| 사진           | 경기당 한 장. 찍기 또는 앨범. 원본 비율 그대로                      |
| 보여 주는 곳   | 경기 상세의 직관 블록, 마이 탭 요약 줄, 직관 기록 화면              |
| 승률           | 승 ÷ 끝난 직관 경기 수 (무승부는 승률을 깎는다)                     |
| 예정 경기      | 언제든 표시할 수 있다. 끝나기 전에는 "예정" 으로 세고 승률에서 뺀다 |
| 저장           | 표 하나(`attendances`) + 비공개 사진 버킷. 로그인 필요              |

**범위 밖**: 위치 인증, 여러 장 사진, 홈 화면 배지, 팬카드 연동, 랭킹·공유, 푸시 알림(개발자
계정 구매 뒤).

## 화면 흐름

### 경기 상세 (포항 경기)

스코어 카드와 예매 단추 아래에 직관 블록을 둔다.

- 표시 안 함: 끝난 경기는 `[직관했어요]`, 끝나지 않은 경기는 `[직관 예정]`
- 표시함: "✓ 직관한 경기" 또는 "직관 예정" 줄, 사진 자리, 작은 `[직관 취소]`
- 사진이 없으면 `[사진 넣기]` → "사진 찍기 / 앨범에서 고르기" 를 고른다. 있으면 썸네일과
  `[바꾸기] [치우기]`
- 비로그인 상태에서 누르면 로그인부터 청한다
- 사진이 있는 기록을 취소하면 "사진도 함께 지워집니다" 확인을 받는다

### 마이 탭

"나만의 카드 만들기" 아래에 `[직관 기록]` 줄. 오른쪽 값은 "7경기 · 71%". 기록이 없으면
값을 비운다. 끝난 경기가 하나도 없으면 "1경기" 처럼 경기 수만 보인다.

### 직관 기록 화면 (새 화면, 이름 `Attendance`)

- 요약: 크게 "승리요정 71%", 그 아래 "직관 7경기 · 5승 1무 1패", 예정이 있으면 "예정 1경기"
- 목록은 최신순. 사진 썸네일(없으면 빈 칸), 날짜, 상대, 스코어, 승·무·패 표시 또는 "예정".
  누르면 그 경기 상세로 간다
- 빈 상태: "경기 상세에서 '직관했어요' 를 눌러 보세요". 비로그인이면 로그인 안내

### 사진

- 누끼를 따지 않는다. 경기장 사진은 가로가 많아 3:4 로 자르지 않는다
- 폭 1600 JPEG 로 줄여 올린다 (`uploadPrivateImage`, PNG 면 PNG 유지)
- 올라가기 전에 로컬 파일로 곧바로 보여 주고, 실패하면 되돌린다
- `expo-image-picker` 설정에 카메라 권한 문구를 더한다: "직관 사진을 찍기 위해 카메라 접근이
  필요합니다." 네이티브를 다시 빌드해야 한다

## 데이터 흐름

### 표 `attendances` (migration 0022)

| 칸                                         | 뜻                                                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| `owner uuid`                               | `auth.users`, 탈퇴하면 함께 지운다 (`on delete cascade`)                     |
| `year int`, `league_id int`, `game_id int` | 경기. `matches` 의 기본 키와 같은 셋                                         |
| `photo_path text`                          | 사진의 버킷 안 경로. 없으면 null                                             |
| `created_at`, `updated_at timestamptz`     | `updated_at` 은 `touch_updated_at` 트리거가 갱신하고 사진 캐시 버전으로 쓴다 |

- 기본 키 `(owner, year, league_id, game_id)`. 두 번 눌러도 한 줄이다
- RLS: select / insert / update / delete 모두 `auth.uid() = owner`
- `matches` 와 외래키로 묶지 않는다. 경기 표를 정리해도 직관 기록은 남는다 — 0021 에서
  경기를 지운 것과 같은 일이 CASCADE 로 기록까지 지우면 안 된다

### 사진 버킷 `my-attendance-photos`

비공개, 5MB, `image/jpeg`·`image/png`. 경로 `{uid}/{year}-{leagueId}-{gameId}` (확장자 없음).
정책은 `my-player-photos` 와 같은 본인 폴더 정책.

### 앱

- `src/repositories/attendance/remote.ts`
  - `listMine(): Promise<AttendanceRow[]>`
  - `mark(match)`: upsert
  - `unmark(match)`: 행을 먼저 지우고 사진 파일을 지운다
  - `setPhoto(match, localUri)`: 올린 뒤 `photo_path` 를 갱신하고 새 행을 돌려준다
  - `clearPhoto(match)`
- `src/hooks/attendance/useAttendances.ts`
  - 질의 열쇠 `['myAttendances', uid]`. 목록에는 주소가 없다
  - 표시·취소는 누르는 즉시 화면에 반영하고 실패하면 되돌린다
  - 사진은 `resolvePrivateImage({ bucket, path, version: updated_at })`, 방금 올린 것은
    `adoptPrivateImage`
- `src/models/attendance.ts`: 순수 함수 `attendanceStats(attended, matches)`
  - 경기마다 `outcomeOf()` 로 승·무·패를 가리고, 끝나지 않은 경기는 예정으로 센다
  - `{ total, wins, draws, losses, upcoming, rate }`. `rate = wins / (wins + draws + losses)`,
    끝난 경기가 0 이면 `null`
  - 포항 경기 목록(`matchService`)에 없는 기록은 계산과 목록에서 뺀다

### 로그아웃

질의 열쇠가 uid 로 갈려 있다. 사진 캐시는 `privateImage` 가 SIGNED_OUT 에 통째로 비운다.

## 오류 처리

| 상황                  | 처리                                                                          |
| --------------------- | ----------------------------------------------------------------------------- |
| 표시·취소 실패        | 화면을 되돌리고 "저장하지 못했습니다"                                         |
| 목록 불러오기 실패    | 경기 상세 단추는 "표시 안 함" 으로, 직관 기록 화면은 `QueryState` 오류·재시도 |
| 사진 올리기 실패      | 방금 고른 사진을 거두고 알린다. 직관 표시는 남긴다                            |
| 사진 내려받기 실패    | 빈 칸. 알리지 않고 다음에 다시                                                |
| 카메라·앨범 권한 거부 | "설정에서 켜 주세요"                                                          |
| 사진 있는 기록 취소   | 확인 → 행 먼저 삭제 → 파일 삭제. 파일 삭제 실패는 알리지 않는다               |
| 비로그인              | 로그인부터 청한다                                                             |
| 올리는 중 화면을 닫음 | 사라진 화면은 늦게 온 결과를 건드리지 않는다                                  |

## 테스트

### 자동 (jest)

- `attendanceStats`
  - 승·무·패를 센다
  - 예정 경기는 승률에서 빼고 `upcoming` 으로 센다
  - 끝난 경기가 0 이면 `rate` 는 null
  - 이번 시즌 목록에 없는 기록은 뺀다
  - 5승 1무 1패면 71% (무승부가 깎는다)
- 사진 경로, 질의 열쇠
- 직관 블록: 끝난 경기 `[직관했어요]` / 예정 `[직관 예정]`, 비로그인이면 로그인을 청함, 표시
  실패면 되돌림
- 직관 기록 화면: 요약 숫자, 빈 상태, 최신순
- 마이 탭: "7경기 · 71%", 기록이 없으면 값 없음

### 배포 뒤 실측

- 0022 적용 후 로그인 없이 `attendances` 와 사진 버킷을 읽으면 막힌다
- 폰: 지난 경기 표시 → 승률 반영, 예정 경기 표시 → "예정", 사진 찍기와 고르기, 재시작 후
  남는지, 취소, 로그아웃 후 다른 계정에서 안 보이는지
- 카메라 권한 문구가 뜬다 (네이티브 재빌드)

## 순서

1. migration 0022 파일
2. 승률 계산(순수 함수)

4. 경기 상세 직관 블록 (사진 포함)
5. 직관 기록 화면과 마이 탭 줄
6. 카메라 권한 설정
7. 0022 적용(SQL Editor, 사용자) → 폰 빌드와 확인
