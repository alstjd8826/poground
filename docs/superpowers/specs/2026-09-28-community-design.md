# 커뮤니티 — 설계

작성 2026-09-28.

## 왜

직관 기록에 사진과 글을 남기다 보면 다른 팬에게도 보여 주고 싶어진다. 포항 전용 팬
커뮤니티 앱은 없고, 다른 구단 팬앱(에버그린, 서울라이트, KickON)은 커뮤니티가 중심이다.
탭은 소식 탭 자리를 커뮤니티 탭으로 바꾼다. 커뮤니티 탭에는 커뮤니티만 두고, 소식·영상은
탭에서 빼 홈의 "더 보기" 로 들어가는 전체 목록 화면으로 옮긴다(2026-09-28 결정).

## 잘 됐다고 보는 기준

- 로그인한 사람은 사진(최대 4장)과 글을 올리고, 글마다 전체 공개 / 나만 보기를 고른다
- 누구나(로그인 없이도) 공개 글을 최신순으로 읽는다
- 게시글·댓글·대댓글에 좋아요를 누르고, 게시글에 댓글을 단다
- 남의 글을 신고·차단할 수 있고, 운영자가 신고함에서 처리한다 (심사 지침 1.2)
- 직관 기록 화면은 내 직관 글을 피드로 보여 주고, 나만 보기 글은 자물쇠로만 구분한다

## 정한 것

| 질문         | 결정                                                                                                                                                                          |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 글 종류      | 직관 글과 자유 글. 본문에 `#직관` 이 있으면 직관 글. 경기를 고르면 본문에 경기 태그(`#9월20일서울전`)가 들어가고 그 태그로 경기를 찾는다 (2026-09-29 변경, 켜고 끄는 칸 없음) |
| 공개 설정    | 게시글 자체의 칸 하나. 전체 공개 / 나만 보기. 수정으로 언제든 바꾼다                                                                                                          |
| 기본값       | 전체 공개                                                                                                                                                                     |
| 반응         | 게시글·댓글·대댓글 좋아요, 게시글 댓글. 댓글 좋아요는 앱 전체 댓글에 적용                                                                                                     |
| 사진         | 글당 최대 4장, 앨범에서만(2026-09-29). 피드는 첫 장 + "+3"                                                                                                                    |
| 피드         | 최신순 하나, `[전체 · 직관 · 자유]` 거르개                                                                                                                                    |
| 읽기         | 누구나. 쓰기·좋아요·댓글·신고는 로그인                                                                                                                                        |
| 글 모양      | 인스타그램식. 제목 없이 사진과 본문(1~1,000자)                                                                                                                                |
| 사진 권한    | 비공개 버킷 하나. 읽기 규칙이 "그 사진의 글이 공개이거나 내 글" 을 본다 — 공개 설정을 바꿔도 파일은 옮기지 않는다                                                             |
| 나만 보기 글 | 커뮤니티 피드에는 없다. 직관 기록과 내 상세에서는 똑같이 보이고 자물쇠 아이콘만 붙는다                                                                                        |

**범위 밖**: 인기순, 해시태그·검색, 알림(푸시는 개발자 계정 뒤), 공유 링크, 동영상, 경기 상세의
"이 경기 직관 후기" 칸.

## 데이터 (migration 0023)

### `posts`

| 칸                                                           | 뜻                                                                           |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `id uuid`                                                    | 기본 키                                                                      |
| `author uuid`                                                | `auth.users`, 탈퇴하면 함께 지운다                                           |
| `body text`                                                  | `char_length(btrim(body)) between 1 and 1000`                                |
| `visibility text`                                            | `'public'` 또는 `'private'`, 기본 `'public'`                                 |
| `match_year int`, `match_league_id int`, `match_game_id int` | 직관 글이면 채우고 자유 글이면 비운다. 셋이 다 있거나 다 없어야 한다 (check) |
| `deleted_at timestamptz`, `deleted_by uuid`                  | 소프트 삭제. 신고 처리 기록이 남아야 한다 (댓글과 같은 방식)                 |
| `created_at`, `updated_at`                                   | `touch_updated_at` 트리거                                                    |

RLS:

- select: (`visibility = 'public'` 이고 `deleted_at is null`) 은 `anon, authenticated` 누구나. `author = auth.uid()` 는 전부
- insert: `author = auth.uid()`
- update: 본인. 관리자(`is_admin()`)는 `deleted_at`·`deleted_by` 만 (소프트 삭제)
- delete: 쓰지 않는다 (소프트 삭제만)

`matches` 와 외래키로 묶지 않는다 (0022 와 같은 이유).

### `post_photos`

`post_id uuid`(posts, on delete cascade), `position int`(0~3, check), `path text`. 기본 키
`(post_id, position)`. 읽기 규칙은 글을 따른다(그 글을 읽을 수 있으면 읽는다). 쓰기·지우기는
글의 작성자만.

### 사진 버킷 `post-photos`

비공개, 5MB, `image/jpeg`·`image/png`. 경로 `{uid}/{postId}/{position}` (확장자 없음).

- select(`anon, authenticated`): `posts` 에서 `id = (storage.foldername(name))[2]::uuid` 인 글이
  (공개이고 안 지워졌거나) 작성자가 `auth.uid()` 일 때
- insert / update / delete: `(storage.foldername(name))[1] = auth.uid()::text`

앱은 기존 `privateImage`(서명 주소로 한 번 받아 버전 붙은 캐시 파일로 둠)를 그대로 쓴다.
버전은 `posts.updated_at`. 로그인 안 한 사람도 공개 글 사진은 서명을 받을 수 있다.

### 좋아요

- `post_likes(post_id, user_id)`, `comment_likes(comment_id, user_id)`. 기본 키가 둘의 조합
- select 는 누구나, insert·delete 는 `user_id = auth.uid()`
- 볼 수 없는 글에는 누를 수 없다 (insert 정책이 글의 select 조건을 다시 본다)
- 뷰 `post_stats(post_id, like_count, comment_count)` — 피드가 한 번에 받는다
- 댓글 좋아요 수는 댓글 목록 질의가 함께 받는다

### 댓글

- `comments.subject_type` check 에 `'post'` 를 더한다
- `subject_type = 'post'` 인 댓글은 그 글을 읽을 수 있을 때만 insert 할 수 있다

### 신고·차단

- `post_reports(post_id, reporter, reason, detail, created_at, resolved_at, resolved_by)` —
  `comment_reports` 와 같은 모양. `(post_id, reporter)` 유일
- 신고함 뷰를 게시글까지 넓힌다: 대상 종류(`comment` / `post`)를 칸으로 둔다
- 신고 메일 트리거(0014 의 `notify-report`)를 게시글 신고에도 건다. 메일 본문에 대상 종류를 적는다
- 차단: 기존 `user_blocks` 를 쓴다. 앱이 차단한 사람의 글을 피드·상세에서 가린다

### 직관 기록 사진 옮기기

`attendances.photo_path` 에 사진이 있는 기록은 그 경기의 나만 보기 직관 글(본문 "직관") 로
옮긴다. 파일 복사는 SQL 로 못 하므로 migration 은 글과 `post_photos` 행만 만들고, 파일 복사는
앱 첫 실행이 아니라 **일회성 스크립트**(Edge Function 이 아니라 로컬 `deno run`, 서비스 키
없이 본인 세션으로)가 한다. 지금 데이터는 본인 계정 몇 건뿐이다. 옮긴 뒤 `photo_path` 칸과
`my-attendance-photos` 버킷은 4단계에서 정리한다.

## 화면

### 커뮤니티 탭 (소식 탭 자리)

- 커뮤니티만 둔다. 하위 탭 없이 `[전체 · 직관 · 자유]` 거르개와 공개 글 최신순 피드, 20개씩 이어
  받기, 당겨서 새로고침
- 오른쪽 아래 떠 있는 `[글쓰기]`. 비로그인이면 로그인부터
- 소식·영상은 탭에서 빠진다. 홈의 소식·영상 칸 "더 보기" 가 홈 스택 위에 전체 목록(`NewsList`,
  `VideoList`)을 밀어 연다. 가장 자주 쓰는 입구(홈 미리 보기)는 그대로다. 마이 탭으로 옮기는 안은
  마이가 "내 것과 설정" 자리라 접었다

### 피드 카드 (커뮤니티와 직관 기록이 함께 쓴다)

- 윗줄: 아바타·닉네임, 상대 시간("3시간 전"), 나만 보기면 자물쇠(벡터 아이콘, 테마 색), ⋮
  (내 글: 수정·삭제 / 남의 글: 신고·차단)
- 사진: 1:1 로 채워 옆으로 넘기고 오른쪽 위에 1/4 (2026-09-29 변경). 사진이 없으면 직관 글이든 자유 글이든
  본문만 — 직관 글은 경기 줄로 알린다(스코어 카드는 뺐다, 2026-09-29)
- 직관 글이면 경기 줄("9/20 vs 서울 2:1 승"), 누르면 경기 상세
- 본문 세 줄, 넘치면 "더 보기"
- 아랫줄: 좋아요 수, 댓글 수. 누르면 상세

### 글 상세

사진 옆으로 넘기기(점 표시), 본문 전체, 좋아요, 기존 댓글 목록·입력 바. 댓글·대댓글에도
좋아요.

### 글쓰기·수정 (한 화면)

- 사진 최대 4장: 앨범(여러 장), 순서 바꾸기, 빼기. 자르지 않는다. 찍기는 없다(2026-09-29)
- 본문 1,000자, 남은 글자 수
- 경기 태그 칩을 누르면 본문에 `#직관` 과 경기 태그가 들어간다. 경기 상세에서 들어오면 미리 들어가 있다
- 공개 설정 토글(기본 전체 공개)
- 헤더 `[올리기]`. 사진을 먼저 올리고 글을 마지막에 만든다 — 반쯤 만들어진 글이 피드에 보이지
  않는다. 실패하면 올라간 사진을 지우고 초안을 그대로 둔다

### 직관 기록 연결

- 경기 상세 직관 블록: 사진 넣기 대신 `[직관 글 쓰기]`. 이미 쓴 글이 있으면 그 카드를 보여 준다
- 직관 기록 화면: 요약은 그대로, 아래는 내 직관 글 피드(자물쇠 포함). 글 없이 체크만 한 경기는
  스코어 카드와 `[글 쓰기]`

## 오류 처리

| 상황                               | 처리                                                                                    |
| ---------------------------------- | --------------------------------------------------------------------------------------- |
| 올리기 중 사진 하나 실패           | 글을 만들지 않고 올라간 사진을 지운다. 초안 유지, "다시 올리기"                         |
| 올리는 중 앱을 벗어남              | 글이 마지막에 만들어지므로 반쪽 글이 없다                                               |
| 좋아요                             | 즉시 반영, 실패하면 되돌림, 끝날 때까지 잠금                                            |
| 나만 보기로 바꿈                   | 커뮤니티 피드에서 즉시 빠진다. 남이 열어 둔 상세는 다시 불러올 때 "볼 수 없는 글입니다" |
| 지워진·볼 수 없는 글에 댓글·좋아요 | 정책이 막고 앱은 "볼 수 없는 글입니다"                                                  |
| 차단한 사람의 글                   | 피드·상세에서 가린다                                                                    |
| 피드 불러오기 실패                 | `QueryState` 오류·다시 시도, 당겨서 새로고침                                            |
| 사진 권한 거부, 5MB 초과           | 기존 안내                                                                               |

## 테스트

### DB 실측 (migration 적용 뒤, curl)

- 로그인 없이 공개 글·사진은 열리고, 나만 보기 글·사진은 막힌다
- 나만 보기 → 공개로 바꾸면 곧바로 열린다
- 볼 수 없는 글에 댓글·좋아요 insert 가 막힌다

### jest

- 피드 카드: 사진 / 스코어 카드 / 본문만, 자물쇠, "+N", 더 보기
- 글쓰기: 사진 4장 제한, 1,000자 제한, 직관 글 경기 고르기, 공개 토글, 올리기 실패 시 초안 유지
- 좋아요: 낙관적 반영, 되돌림, 연타 잠금
- 거르개, 차단한 사람 가리기
- 직관 기록 피드와 승률 (기존 테스트 유지)

### 폰

두 계정으로 공개·나만 보기가 서로 어떻게 보이는지, 신고가 신고함과 메일로 오는지.

## 나눠서 만들기

스펙은 하나, 구현 계획은 단계별. 단계마다 폰에서 확인하고 merge 한다.

1. **DB 와 읽기**: 0023, 피드, 상세, 커뮤니티 탭 개편
2. **쓰기**: 글쓰기·수정(사진 4장), 삭제, 공개 설정
3. **반응과 관리**: 게시글·댓글 좋아요, 게시글 신고·차단, 신고함·신고 메일 확장
4. **직관 기록 연결**: 직관 블록의 `[직관 글 쓰기]`, 직관 기록 피드, 옛 직관 사진 옮기기와 정리

## 개인정보 방침

- 1-2 표: 게시글(사진·본문) — "전체 공개면 다른 이용자에게 공개, 나만 보기면 본인만"
- 2절 공개 범위 표에 게시글을 넣는다
- 이미지 안내 문단: 게시글 사진은 글이 공개일 때만 다른 사람이 열 수 있다
